# TheBurntPeanut Bingo

A realtime two-player bingo game built with React, Vite, Tailwind CSS, and Supabase. Players create or join a shared game, mark squares on their own board, and race to complete a row, column, or diagonal.

## Features

- Create a new game and share the generated Game ID
- Join an existing game by Game ID
- Action-first lobby that asks for details only after choosing create or join
- Branded logo and browser tab icon
- Random 5x5 bingo boards with a marked free center square
- Realtime board, winner, score, and round updates through Supabase
- Per-player session restore from local storage
- Winner modal with play-again voting
- Automatic next round once all players vote to play again
- Lobby reset that deletes the active game and returns players to the lobby

## Tech Stack

- React 19
- Vite 8
- Tailwind CSS 4
- Supabase JavaScript client
- ESLint

## Getting Started

### Prerequisites

- Node.js
- npm
- A Supabase project

### Install dependencies

```bash
npm install
```

### Configure environment variables

Create a `.env` file in the project root:

```env
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
```

Vite only exposes environment variables prefixed with `VITE_`, so keep those names exactly as shown.

### Supabase tables

The app expects these public tables.

#### `bingo_phrases`

Stores the phrases used to build bingo boards. Add at least 24 rows before creating a game.

| Column | Type            | Notes                              |
| ------ | --------------- | ---------------------------------- |
| `id`   | UUID or integer | Primary key                        |
| `text` | text            | Phrase displayed in a bingo square |

#### `games`

Stores each game and round-level state.

| Column          | Type    | Notes                                      |
| --------------- | ------- | ------------------------------------------ |
| `id`            | UUID    | Primary key, generated by Supabase         |
| `player1_name`  | text    | Creator's name                             |
| `player2_name`  | text    | Joining player's name                      |
| `player1_score` | integer | Defaults to `0`                            |
| `player2_score` | integer | Defaults to `0`                            |
| `winner`        | text    | Nullable winner name for the current round |
| `round_number`  | integer | Defaults to `1`                            |

#### `game_players`

Stores each player's board and round state.

| Column        | Type    | Notes                              |
| ------------- | ------- | ---------------------------------- |
| `id`          | UUID    | Primary key, generated by Supabase |
| `game_id`     | UUID    | References `games.id`              |
| `player_name` | text    | Player display name                |
| `board`       | jsonb   | 25 board cells                     |
| `marked`      | jsonb   | Currently unused by the UI         |
| `has_won`     | boolean | Defaults to `false`                |
| `voted`       | text    | Play-again vote state              |

Enable realtime changes for the `games` and `game_players` tables so connected players receive updates without refreshing.

## How The Game Works

1. A player chooses Create Game, enters their name, then starts the game.
2. The app creates a row in `games`, creates the player's row in `game_players`, and saves the session locally.
3. Another player chooses Join Game, enters their name and the Game ID, then joins the same game.
4. Each player receives a randomized board from `bingo_phrases`.
5. Marking a square updates that player's board in Supabase.
6. Completing a row, column, or diagonal marks the round winner and increments their score.
7. When all players vote to play again, the app generates fresh boards and advances the round.

## Notes

- The free center square is always marked.
- A game needs at least 24 phrases because the center square acts as the free space.
- Browser local storage is used only to restore the current player's active game session.
- Supabase row-level security policies should allow the reads and writes your deployment needs.
